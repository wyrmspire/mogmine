## 2. Small designs

### 2.1 Challenge floor label (UX-07)

`components/ChallengeCard.tsx` shows the Drawdown Defender floor as a dollar figure near the account money, so "$50" (the room left, or a floor offset) reads like equity. Change: label the number by what it is, always with its unit and basis: `Room before the challenge limit: $50 (from your high point)`. Under Shield: `Room: 3% of the limit`. Same copy rules as docs/21 §5 ("From your journal · gross").

### 2.2 Challenges per account (UX-08)

- `ChallengeDefinition` gains `account_id: string | null` (null = all accounts, today's behaviour, so existing challenges do not change).
- The setup sheet (`components/ChallengeSetupSheet.tsx`) gets the account picker (`components/AccountSelect.tsx`) defaulting to the account used last; hidden when there are no accounts.
- `lib/challenges.ts` filters trades by `account_id` when set. Drawdown Defender with an account uses that account's own trades only; it still does not read the account's loss rules (docs/17 keeps them separate; `docs/21` step 4 is not in scope).
- The challenge card names the account.
- Jsonb record, so no migration; sanitizer and the command layer accept the field.

### 2.3 Future dates and impossible prices (UX-09)

| Check | Form (`lib/entry-form.ts`, `validateTradeInput`) | Command layer / API |
| :--- | :--- | :--- |
| Entry more than 5 min in the future | Error: "This entry is in the future (Tue, Nov 24 09:10 CT). Check the date." | 422, same text |
| Exit in the future | Error (open trades have no exit) | 422 |
| Price far from the market | Warning when the day's bars are loaded and the price is more than 1% outside that day's range: "4866.25 is far from where MES traded that day (6935–7410). Typo?" Saving is still allowed. | warning `price_out_of_range` ([07](07-agent-api.md) §4) when the server has the bars; otherwise none |

The price check is a warning, not an error: Yahoo can be missing bars, and the trader's fill is the fact (B-12). *(Decision Q-10.)*

### 2.4 No setup picked (UX-14)

- The Pit Stop (`components/PitStop.tsx`) shows "No setup picked" as the first chip row's placeholder when `playbook_id` is null, in the muted style, with the playbooks as chips right there. Not a modal; not blocking.
- Review queue cards and the daily review show the same "No setup" chip, so it is easy to fix in one pass.
- The agent side is the `playbook_missing` warning and HR-3 ([07](07-agent-api.md)).

### 2.5 Notes fields say what they are for (UX-18)

Placeholders that steer away from restating fields:

| Field | Placeholder |
| :--- | :--- |
| `pre_trade_thesis` | "Why this trade? What did you see?" |
| `management_notes` | "What did you decide during the trade, and why?" |
| `post_exit_notes` | "What would you do differently?" |
| `note` | "Anything else worth remembering" |

A muted hint under the notes block: "Prices, stop, risk and R are saved above. Notes are for your thinking." No validation in the app: the trader may write what they like. (The API warns; the app does not.)

### 2.6 Initial stop time for API trades (UX-19)

PR #202's "Initial stop 7444.00, set 09:50 · stop trailed to 7350.00" needs `initial_stop_set_at`. The command layer requires the price and time together (`journal-commands.ts`), so an agent that sends only `initial_stop_price` gets a 422 and often sends the entry time as the set time (which then caused the false SL touch, [05](05-stops-mae-fills.md) §2). Change: when `initial_stop_price` is sent without a time, **default `initial_stop_set_at` to the entry time** (the stop was set at entry, R-10's meaning) and return a warning `initial_stop_time_defaulted`. Combined with SM-UT-1 (move time never taken from `initial_stop_set_at`), this is safe.
