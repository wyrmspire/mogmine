Spec: `docs/23-card-system.md` §5.1, §7 (warm-up before the open), §9 (teach the rule on the reveal; pin a teaching example).

## What changed

1. **Drill reveal rule note** (`lib/drills.ts` `drillRevealRuleNote`, `components/DrillScreen.tsx`)
   - `broken` names the first unchecked frozen rule with `followed/total`; `clean` says all rules followed; `none` shows nothing.
   - The reveal shows the trade's playbook name even on Warm-up and Misses decks.
2. **Pre-open warm-up** (`lib/drills.ts` `isPreOpenWarmupWindow`, `components/TodayScreen.tsx`)
   - America/New_York via `Intl.DateTimeFormat`. Mon–Fri, 06:00 up to 09:30 ET, and at least one `drillSkipReason(...) === null` trade.
   - Today only (not past days). Renders a 44px link to `/drills`: "Pre-open warm-up · 5-card Take it? deck →".
3. **Pinned example** (`lib/playbooks.ts`, `lib/playbooks-sanitize.ts`, `lib/playbooks-store.ts`, `lib/playbook-card.ts`, `components/PlaybookCard.tsx`)
   - Optional `pinned_example_trade_id` on `Playbook`. `sanitizePlaybook` and `clonePlaybook` set it only for a non-blank string, so an unpinned key is never written and `PLAYBOOK_SEEDS` / `seedFingerprints` are unchanged.
   - `setPlaybookPinnedExample(playbookId, tradeId | null)` persists and calls `playbooksSync.changed()`.
   - `playbookExample(id, trades, pinnedTradeId?)` returns the pin first (basis `"pinned"`) when it is a closed, non-sample trade of that playbook. Otherwise it falls back to `clean_take`, then `clean`.
   - Card: "Pin example" / "Pinned example" toggle (`aria-pressed`, 44px), plus a select listing the playbook's closed real trades with "Automatic" as the default.

## Deviations and choices

- Pin controls show when there is an example **or** at least one closed real trade of the playbook, so a trader can still pick a trade when no example is auto-selected. The spec said "when `example` exists".
- `lib/playbook-binder.ts` is read-only for this package, so its caption function does not know the `"pinned"` basis. `PlaybookCard.tsx` shows "Pinned teaching example" for that basis and calls `playbookExampleCaption` otherwise.
- `lib/playbook-card-image.ts` (read-only) may still caption a pinned example with the automatic wording on the exported share PNG. Needs a follow-up in an owned package.
- `drillRevealRuleNote` keeps the `playbook_id` argument from the spec signature; it is unused.
- Component changes (DrillScreen, TodayScreen, PlaybookCard) are checked by typecheck only. No component render tests exist for them in the targeted set.
