## Concerns for the reviewer (in priority order)

1. **Untouched seeds overwrite a server rename on first sign-in (data loss; sync-layer rule, not fixed here).**
   The playbook seeds have the same stable ids on every device. A fresh device that has never synced has an empty base,
   so its untouched seed counts as dirty and wins in `pull()` rule 2. It then pushes over the server copy.
   Reproduced with a throwaway probe test (deleted afterwards):
   the server held `orb-reclaim` renamed to "RENAMED ON DEVICE A"; after a fresh device's sign-in and pull, both the local
   and the server name were "ORB Reclaim".
   This is the same shape as #190 open question 1, but it hits every new device for the four seeds.
   The brief says importing seeds is fine, and I followed it. Options for the reviewer: (a) on a device's first pull,
   prefer the server copy for any id it holds unless this device edited the record (needs an "edited on this device" bit);
   (b) only push seeds the trader has changed. Option (b) keeps the seeds out of the base until they differ, so it is a
   store-side change, but it needs care with `removes` (a seed kept out of `getLocal` would look removed).
2. **Restore that drops a playbook leaves the server row active (archive policy).** `restorePlaybooks` drops the id locally,
   which puts it in `gone` when the push gets `forbidden`. The server row stays active and the device reports `synced`,
   so the playbook reappears on other devices. Probe confirmed: the row is unchanged after the restore. Options: have
   restore archive missing playbooks (not drop them), or have the archive-policy remove write `archived: true`. Either is a
   behaviour decision, so I did not make it.
3. **Same-id first-sign-in conflict** (#190 open question 1) applies to plans and drills too. Not changed.
4. **Cross-tab listeners.** Playbooks already had a `storage` listener, and it now calls `changed()`. Plans and drills have no
   listener today, and I did not add one.
5. **Docs not updated.** `docs/26` §6 and §8 should list the three stores as synced. That file is outside this brief's
   writable list, so the reviewer should update it.
