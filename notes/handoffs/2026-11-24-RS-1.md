## Behaviour

- **Fallback order (D-B, Q-12, Q-13):** trade's frozen `r_size_cents` → account's `r_size_cents` → `prefs.riskBudgetUsd × 100` (default `25000`, `source: "prefs"`). Unassigned trades go straight to prefs.
- **`resultR`** = gross P&L cents ÷ R size. Defined for any closed trade with a computable P&L, with or without a stop. Null for open trades.
- **`riskR`** = `riskCents` ÷ R size. Falls back to `stated_risk_r` when there is no stop. Null otherwise, never 0.
- **`riskCents`** = |entry − stop| in ticks × tick value × quantity, in integer cents. The stop is `riskStopPrice` (initial stop when on the risk side, else working stop).
- **`risk_cents`** is recomputed in `normalizeTrade` on every normalize. The command layer refuses a client value that differs (`null` matches `null`).
- **Freezing:** `addTrade` freezes when `r_size_cents` is null. `updateTrade` and the command `update` re-freeze when `account_id` changes, and also when the stored value is still null (see choices).
- **Restore:** `replaceTrades` keeps the device's frozen `r_size_cents` when the incoming row has null. An incoming non-null value is kept as sent.

## Choices I made (the spec did not settle these)

1. **`keepFrozenRSize` lives in `lib/trades.ts`**, next to `keepInitialStop`, not in `store.ts`. The package allowed either. `store.ts` imports it.
2. **A save with a null `r_size_cents` freezes it** (store `updateTrade` and command `update`), not only an account change. This follows 04 §5.6 ("resolves from the account at read time until the trade is saved again"). A legacy trade is frozen the next time it is saved.
3. **`resolveRSize` and `riskR` use the recomputed `riskCents`**, not the stored `risk_cents`. They are equal by construction, since `normalizeTrade` recomputes it.
4. **`riskCents` reuses `riskStopPrice`** through `{ ...trade, exit_price: null }`. That keeps one definition of the risk-side stop rule.
5. **Command `update` drops the stored `risk_cents` before parsing** unless the patch sets it. Without this, a quantity or stop change would be refused as a mismatch against the old stored value.
6. **Import cycle:** `trades.ts` → `r-size.ts` → `trades.ts` (and `accounts.ts` → `r-size.ts`). It is safe at runtime because the cycle only ever calls functions, never at module load. Tests and build pass with it. Say if you would rather break it by moving `riskCents` into `trades.ts`.
