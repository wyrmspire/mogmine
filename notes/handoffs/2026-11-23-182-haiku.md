## Deviations from the brief (and why)

1. `useAuth()` also returns `message` (friendly error copy). The brief's shape had no slot for it.
2. `LoginScreen` takes an optional `auth` prop. `AuthGate` passes it on `/login` in supabase mode; the page renders `<LoginScreen />` with no props, and the gate-off message is shown there.
3. "Not set up" mapping matches on the message (`signups not allowed`, `user not found`, `otp_disabled`, `signup_disabled`) rather than on status 422 or 400 alone, so an unrelated 400 is not labelled "not set up". Rate limit: status 429, or `rate limit` / `rate_limit` / `too many` in the text.
4. Any `#error=` hash maps to the expired-link copy. The brief asked for that copy; other error codes are not distinguished.
5. Sign-out uses `window.location.replace("/login")` instead of `assign`, to avoid a lint warning and keep the signed-in page out of history.
6. `getAuthClient()` casts the SDK client to `AuthClientLike` (`as unknown as`). The cast is not checked against the SDK's own types; the runtime checks above are what cover it.
7. `isAuthGateOn` uses `chooseAdapter` from `select.ts` directly. The test imports it without trouble, so the copy was not needed.
8. The `EMAIL` regex and the `ALLOW_LIST_TABLE` name are in `auth.ts`; the table name matches the migration (`mogmine_allowed_users`).

## PR body

## Summary

- `/login` signs in with an email magic link (implicit flow). `shouldCreateUser: false`, so there is no sign-up. The link works when it opens in another browser (iPhone Mail).
- In `supabase` mode, `AuthGate` wraps the app. Only a user whose own `mogmine_allowed_users` row is readable gets in. Anyone else sees "Not authorized" and `AppShell` never mounts, so no app data loads.
- Header sign-out button. An expired or reused link shows a clear message and clears the hash.
- `local` and `mock` modes are unchanged: no gate, no login, no Supabase SDK fetch.

## Security notes

- No PKCE and no code exchange. The implicit flow needs no code verifier stored in the browser that asked for the link.
- Anon key only in the browser. No service-role key in any file here; a test guards this.
- The allow-list check selects the user's own row (RLS `mogmine_allowed_users_read_own`). Any error counts as "error", never as allowed.
- Exactly one `createClient(` call in production source (test-guarded).
- The built-in mailer allows 2 sign-in emails an hour, so a rate-limited response is mapped to a clear message, and the raw server text is never shown.

## Review (grok-bot)

- `useAuth`: a `TOKEN_REFRESHED` / repeat `INITIAL_SESSION` for the already-checked user no longer flips the gate to "checking", which would have unmounted AppShell (and lost unsaved edits) on every hourly token refresh.
- `useAuth`: the allow-list query is deferred out of the `onAuthStateChange` callback (`setTimeout 0`), per supabase-js guidance that database calls inside the callback can deadlock on the auth lock.
- `LoginScreen`: renders `<main>` only when the gate is on; in local/mock it sits inside AppShell, which already owns `<main>`.
