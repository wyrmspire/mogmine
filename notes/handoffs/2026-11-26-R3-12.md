## What changed

- **`components/PartialsCard.tsx`** (new, 220 lines, limit 450 / guideline 220):
  - `buildPartialsCardView(trade, rSize, shield, zone)`: pure. Returns `null` without `partial_exits` or `partial_targets`, except a closed trade with targets and a top-level exit is represented by a synthetic full-quantity exit. Uses `calculatePartials` with `rSizeCents: rSize.cents`.
  - Regression test confirms a closed trade with targets and no partial exits shows its realized close, while an ordinary trade with neither remains hidden.
  - Averages are text in the fills table caption (`Avg entry … · Avg exit …`), not extra rows.
  - Under `shield`: quantity columns are removed, and no `$` figure is returned.
  - `PartialsCard` renders the planned-targets table and the executed-fills table, both with `tabular-nums`.
  - `PlanVsActualSection` is the old inline table, moved. It uses `var(--profit-text)` and `var(--loss-text)` instead of the hex values. It renders nothing without a plan.
- **`components/TradeDetail.tsx`**:
  - `showRuler: detailLevel === "high"`, replacing `true` (UX-E2 / D-V2).
  - `calculateExitEfficiency(trade, mfe, { accounts: accountsState.accounts, prefs })` and `derivePlanVsActual(trade, { accounts: accountsState.accounts, prefs })`. Both `useMemo` dep lists include `accountsState.accounts, prefs`.
  - The inline plan-vs-actual JSX is replaced by `<PartialsCard … />` and `<PlanVsActualSection … />`.
  - Chart detail state is typed `DetailLevel` (`low | medium | high`) so the `"high"` comparison type-checks. The hindsight call passes the literal `"medium"`, since that branch is already `!== "low"`.
