# R3-07 — partial_exits and partial_targets on TradeRecord, fromLegacy, and journal-commands (#38)

Bot r3-1 (finish mode), wave 3. Depends on R3-01 (`partials.ts`) and R3-03.

## What changed

- **`lib/partials-record.ts`** (new, 145 lines): `sanitizePartialExits` (sorted by time, `undefined` when empty), `sanitizePartialTargets`, `validateTradePartials` (422-style `string | null` for journal-commands), `partialsTradeMetrics` (delegates to `calculatePartials`; `null` when open or without partials), `chronologicalSeq` (renumbers a partial trade's events in time order, exit legs before same-instant stop moves).
- **`lib/trades.ts`**: `partial_exits?` / `partial_targets?` on `TradeRecord`, re-export of `PartialExit` / `PartialTarget`, sanitized in `normalizeTrade`. `tradeTicks` (average ticks), `tradePoints`, `tradePnl`, `riskMultiple` take the exact multi-lot path via `partialsTradeMetrics` when the trade is not open and has partial exits. Single-lot trades keep the existing code path.
- **`lib/trade-document.ts`**: `TradeDocAnnotations` gains `partial_exits` / `partial_targets` (validated in `isAnnotations`). `fromLegacy` builds plan targets from `partial_targets` (falls back to `planned_target_price`), emits one stated exit fill per leg (with `reason` only when a valid reason is set, `reason_basis: "stated"`), and suppresses the lumped exit fill when legs exist. Partial trades are re-sequenced chronologically.
- **`lib/commands/journal-commands.ts`**: one import and `validateTradePartials(raw, trade)` chained onto the existing `stopMoveError` check in `parseTrade`. A failure returns `invalid`. Chained onto the existing line so the file stays at the cap.
- **`lib/__tests__/partials-wiring.test.ts`** (new, 189 lines): 9 tests covering Fixture 7 (`+$87.50`, `riskMultiple 1.75`, `resultR` at $300), the deriver's outcome and 2 closed lots, stop-move ordering, the open scale-out (`open_qty 1`, one closed lot), sanitizers, validator rules, journal-commands accept/refuse, and the backup round trip.
