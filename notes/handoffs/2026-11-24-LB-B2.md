Package: `LB-B2` (wave 6, swarm-3). Branch `swarm/LB-B2`. Depends on LB-B1, SM-3, DR-2 (all merged).

**MIGRATION:** none in this PR. Nothing to apply.

## What changed

- `components/LevelCard.tsx` (new, 200 lines): `LevelCard` (non-modal `role="dialog"`, `aria-label="Session level details"`, closes on ×, Escape, or 6000 ms), `LevelsDisclosureList` (`Tap | Always` toggle bound to `setPrefs({ levelLabels })`, a `<details>` list with focusable rows that call `onHighlightTick(tick)` on focus/hover and `null` on blur/leave), and pure helpers `formatLevelCardData`, `clampPopoverPosition` (4 px edges, top ≥ 32 px HUD band), `selectExportLevelPills` (key level first, then nearest groups, ≤ 4 total, no entry/stop/target), `levelHitForTick`.
- `components/TradeChart.tsx`: open-card state and the card as a DOM sibling of `.chart-host` (outside the canvas, so `takeScreenshot` never draws it). Tap, pan, wheel and zoom dismiss it. New prop `highlightedLineTick`. `screenshot()` now swaps to ≤ 4 export pills with the matching right offset in `"tap"` mode, takes the canvas, and restores live `"tap"` mode in a `finally`. The draw path shares a `paintLevels` helper with the export path.
- `components/TradeDetail.tsx`: import, one state line, one mount line (`<LevelsDisclosureList …/>` inside the existing View levels row), and the `highlightedLineTick` prop on `<TradeChart>`. **Net +4 lines** (budget ≤ 10).
- `app/levels.css` (new): all `.level-card` and level-list rules, solid `var(--bg-elevated)` surface, `tabular-nums`, 44 px tap targets.
- `app/layout.tsx`: one import, `import "./levels.css";`.
- `lib/__tests__/level-card.test.ts` (new, 7 tests): see "Deviations" for why these read source instead of importing the helpers.

**Not changed:** `components/TradeCardSheet.tsx`. It never calls `screenshot()`; the export lives in `TradeDetail` → `TradeChart.screenshot()`.

## Deviations and open items (for the planner)

1. **Helper unit tests are not runnable as specified.** The prompt puts the pure helpers in `components/LevelCard.tsx`, which needs JSX. `node --test` here loads `.ts` only and there is no tsx loader. `lib/__tests__/level-card.test.ts` therefore checks the wiring by reading source (the `a11y-core-screens` pattern). It does **not** exercise the clamp, selector, or formatter. Fix: allow a `.ts` module (e.g. `lib/level-card.ts`) for the pure helpers, which is out of this lane's listed files, so I stopped there.
2. **No canvas ray emphasis for `highlightedLineTick`.** `SessionLevelsPrimitive.ts` is not writable here. Focusing a list row instead opens the level card at that ray (DOM, in the chart frame). A true emphasised ray needs a `highlightedTick` option on `SessionLevelsPrimitive.update` and is a follow-up.
3. **Source shows `planned`, not `planned: <session>`.** `LevelLine` carries no plan or session name. `keys` holds only `plan:<planId>:<levelId>`. Fixing it needs a field on `LevelLine` (`lib/chart-levels.ts`, not writable).
4. **No partial-coverage tag.** `LevelLine` has no coverage field, so the card shows only the `proxy` tag. Withheld levels are never drawn, as specified.
5. **Prop name:** `onHighlightTick` (the argument is a tick), not `onHighlightPrice`.
6. **Claim ref:** `refs/heads/claim/LB-B2` already existed on origin at `main` (`3a4d0a5`), so the claim push was skipped.
7. **Browser check not done.** The 390×844 tap, overflow, and `.chart-hud` overlap checks need a running app with auth and bars. This worker did not run them. The `takeScreenshot` behaviour was confirmed from the lightweight-charts 5.3.0 source (`_internal_takeScreenshot` flushes a pending draw before capture, so the export pills and offset are in the PNG), not in a browser.
8. Full `npm test`, `npm run lint`, and `npm run build` were not run (swarm §6b). The wave tester owns them.
