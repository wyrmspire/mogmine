# R3-02 — offset/range pagination for CollectionRepository.list and full-history pull in store-sync

Spec: MOGMINE-BLUEPRINT.md §3.4 (sync integrity: paginate collection sync). Depends on: none.

## What changed
- `lib/persistence/contract.ts`: `ListQuery.offset?: number` (0-based, applied before `limit`).
- `lib/persistence/supabase-adapter.ts`: `QueryLike.range?(from, to)` (inclusive). `collection.list` uses `.range(offset, offset + pageLimit - 1)` when `offset > 0` and `range` exists (`pageLimit` = `limit`, else 1000). Offset 0 / undefined keeps `.limit(...)`. A double without `range` reads `limit + offset` rows and drops the first `offset`.
- `lib/persistence/local-adapter.ts`: `start = max(0, floor(offset))`, slice `[start, start + limit)`.
- `lib/__tests__/fake-supabase.ts`: `range(from, to)` on the builder (`slice(from, to + 1)`).
- `lib/persistence/store-sync.ts`: `MAX_PULL_PAGES = 50`. New module-level `listAllRemote()` pages `list(owner, { includeSamples, includeArchived, limit: REMOTE_ROW_CAP, offset })` in steps of 1000. It stops on a short page, on `MAX_PULL_PAGES` (truncated), or when a full page repeats ids already read (a source that ignores `offset`: truncated, same safety as before). Rows are deduped by id, first-seen order kept. `pullOnce` uses `maybeTruncated` from it, so a finished pull can drop clean server-deleted rows on collections over 1,000 rows.
- `lib/__tests__/store-sync-pagination.test.ts` (new): local and supabase offset/limit paging; 2,350-row pull = 3 selects (1000 + 1000 + 350); delete of clean trade #5 with 2,349 rows left drops it and keeps dirty edit on #2,100.

No migrations, no `docs/26-…`, no `NOTES.md`, no PRs #71 / #271 / `feat/databento-mes-1m` touched.
