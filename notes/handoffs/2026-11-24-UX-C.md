# UX-C — Refuse future trade times, warn on far-off prices (UX-09, 02 §2.3)

**Migration:** none. No SQL, nothing to apply.

## What changed
- **Future times refused (Q-10, Q-11):** `validateFutureTimes` + `FUTURE_ALLOWANCE_MS = 5 * 60_000` in `lib/entry-form.ts`.
  - Entry `> now + 5 min` or closed-trade exit `> now + 5 min` → error text `This entry|exit is in the future (<zone time>). Check the date.`
  - Open trades have no exit, so no exit check.
- **Command layer (`422 invalid`):** `parseTrade(raw, nowMs)` in `lib/commands/journal-commands.ts` returns the error. `createJournalCommands(repos, owner, { now })` injects the clock (default `Date.now`). Create and update check times. Archive does not, so legacy rows can still be archived.
- **Form:** `AddTradeSheet.tsx` assigns the future errors to `errors.entryClock` / `errors.exitClock`, so they block submit and show after the first submit attempt, like the other date errors.
- **Price warning (Q-10, warn only):** `checkPriceAgainstDayRange` in `lib/entry-form.ts`. The sheet keeps the bars the finder loaded (`dayBars`, keyed by the day window's `from`). A typed entry or exit price outside `[dayLow*0.99, dayHigh*1.01]` shows `.banner.warn`. Saving is never blocked.
- **Tests:** `lib/__tests__/future-and-range-validation.test.ts`, 5 tests.
