# UX-B: Challenges per account and challenge room label

Package `UX-B` (wave 4, lane L2). Branch `swarm/UX-B`. Design refs: `02-ux.md` §2.1 (UX-07), §2.2 (UX-08); `docs/17` golden invariants.

**No migration.** `mogmine_challenges` stores `record jsonb`; nothing to apply.

## What changed

- `lib/challenges.ts`
  - `ChallengeDefinition.account_id?: string | null` (absent or `null` = all accounts, today's behaviour).
  - `evaluateChallenge` drops trades whose `account_id` differs, before Drawdown Defender or Clean Run sees them. Null scope is unchanged. Account loss rules are not read.
  - New pure `formatChallengeRoomLabel(roomCents, limitCents, shield)`. Non-Shield: `Room before the challenge limit: $50 (from your high point)`. Shield: `Room: 3% of the limit` (no `$`).
- `lib/challenge-sanitize.ts`: `sanitizeChallenge` writes `account_id` (legacy records and empty strings become `null`).
- `lib/challenge-store.ts`: `startChallenge(rules, started_at, account_id = null)`. There is no `createChallenge` in this codebase, so `startChallenge` is the creation path.
- `lib/commands/journal-commands.ts`: `parseChallengeRecord` (exported, so tests can call it directly) accepts `account_id` that is omitted, `null`, or a non-empty string. Anything else returns `invalid`. Wired into `COLLECTION_PARSERS.challenges`.
- `components/ChallengeSetupSheet.tsx`: account `<select>` ("All accounts" = `null`, default `defaultAccountId(...)`), hidden when there are no active accounts. Passes `account_id` to `startChallenge`.
- `components/ChallengeCard.tsx`: exported `ChallengeAccountBadge` (account name, or "Removed account"). Shown in both challenge rows. Drawdown room line uses `formatChallengeRoomLabel`, in Shield and non-Shield.
- `components/ChallengeDetail.tsx`: badge in the header; "Room Remaining" value uses `formatChallengeRoomLabel`.
- Tests: `lib/__tests__/challenges.test.ts`, `lib/__tests__/challenge-store.test.ts`. Existing fixtures gained `account_id: null`. One existing `deepStrictEqual` in the store test now expects `account_id: null`. Existing golden assertions are otherwise unchanged. New tests cover account-scoped Drawdown and Clean Run, legacy normalization, `startChallenge` with an account, command-layer validation, and the room label.

## Decisions and deviations (for the planner)

1. **`account_id` is optional on the type** (`account_id?: string | null`), not required as the prompt specifies. Two unlisted test files, `lib/__tests__/challenge-sync.test.ts` and `lib/__tests__/sync-restore-and-refresh.test.ts`, build `ChallengeDefinition` literals without the field, and the required type breaks typecheck. They are out of scope, so I did not edit them. Runtime behaviour is identical (`undefined` and `null` both mean all accounts). Making it required later means adding `account_id: null` to those two files.
2. **No `AccountSelect` in the setup sheet.** `components/AccountSelect.tsx` labels the empty option "No account", which reads as "no scope", and that file is not writable in this package. The sheet has an inline select labelled "All accounts" instead. Reusing `AccountSelect` would need a label prop, which is a change to an unlisted file.
3. **"One active challenge per kind" is still global** (`startChallenge` refuses a second active Drawdown or Clean Run regardless of account). This matches `docs/17` §5 and was not in the spec. Per-account concurrency is a product call. Flagging it, not changing it.
4. **Chart legend "Floor: $…"** in `ChallengeDetail.tsx` (the equity-level floor on the chart) is left as is. It is a level, not a room, and the spec's UX-07 text names the room. Say if you want it relabelled too.
