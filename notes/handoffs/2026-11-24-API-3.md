## Response shapes

Both use the standard `{ ok: true, data }` envelope.

- `GET /candles` → `data: { symbol, ticker ("MES=F"), timeframe, provider, from, to, reason?: "closed"|"future", bars: [{time, iso, ct, open, high, low, close, volume}], coverage: {expected, present, gaps: [{from, to, bars}]} }`.
- `POST /checks/trade` → `data: { fills, stop_moves, findings, warnings, refusal, derived, window }`. `refusal` is the message a save would be refused with (422 on save), reported as a field, not an HTTP error.

## Decisions (for the planner to confirm)

1. **Scope for the POST.** `authenticateAgent` in `lib/agent/server-auth.ts` maps the method to a scope, so a POST would demand write. `/checks/trade` runs auth on a GET-shaped copy of the request (same URL and headers) so it is read scope, as docs/07 §5 says. The copy is in one place, with a comment. Test: a read-only key gets 200 and the owner's database has zero rows afterwards.
2. **Pipeline.** Neither route goes through `dispatchAgentRoute`. Both mirror the `guide` route's pattern. Trade check reads through the journal commands, with write calls absent.
3. **Rate limits.** Candles keep a separate general counter (120/min, like the guide route). `handle.ts`'s shared limiter is not exported. The docs say candle calls share the per-key limit; that needs the shared limiter exported (follow-up, outside this package). The upstream cap (15 misses/min per token id) is as specified.
4. **Malformed JSON on `/checks/trade` is 422**, as the prompt says. The other agent routes answer 400.
5. **`risk_r` is unrounded** (`8750 / 30000`), the same value `/records?include=derived` returns. docs/07 §3.3 shows `0.29` for display. The test asserts within 0.005.
6. **`dayPriceRange` is null** in trade checks. The window's own range is not the trading day's range, so it would give false `price_out_of_range` warnings.
7. **Coverage** counts expected bars up to `min(to, now)`. A window whose `to` is past `now` is not clamped in the response. Cache TTL is 10 minutes when `to <= now`, 1 minute otherwise.
8. **`reason: "closed"`** means the window has no regular trading time and the provider returned nothing. That is a weekend in the tests.

## Follow-ups (outside this package)

- `lib/agent/server-auth.ts`: an explicit `scope` option for `authenticateAgent`, so the GET-shaped view can go.
- `lib/agent/handle.ts`: export the shared limiter if candles and checks should count against the same per-key limit.
- `lib/agent/house-rules.ts`: `/guide` should mention the two new endpoints and the 422 `refusal` convention.

No migration. No live Yahoo calls. No real tokens or trades touched. Test fixtures are synthetic bars built from the design's Trade A and C prices.
