## PR body

### Summary
- `/settings/agent`: create agent keys (label, read or read-write), show the plaintext once with a copy-ready setup block, list and revoke keys, show the last 20 agent requests. Behind the #182 sign-in. Gate off shows a notice and loads no SDK.
- `GET /api/v1/openapi.json`: an OpenAPI 3.1 spec generated from the route list and the registry enums, bearer auth declared, no data.
- `GET /.well-known/mogmine.json`: base URL, spec URL, auth scheme, scopes, version, and whether the API is on.
- Header key-icon link (`AgentKeysLink`) and an "Agent keys" link on the login screen's signed-in view.

### Security notes
- The plaintext key lives in component state only. It is never in localStorage, the URL, logs or the database. "Done" clears it. Only `hashAgentToken` output is inserted.
- The browser selects only the columns in `AGENT_KEY_COLUMNS` and the audit columns, never `*` and never `token_hash`. Inserts and revokes go through RLS (anon key plus the owner's session). Revoke sets `revoked_at` and is filtered by id and owner.
- The discovery routes are public but expose no user data. The spec and discovery JSON are tested for: no `mmk_` token shape, no `token_hash`, no "service". `enabled` is a boolean only.
- `SUPABASE_SERVICE_ROLE_KEY` is still read only in `lib/agent/server-auth.ts` (guard test). The well-known route reaches it via `defaultAgentDeps()`.
- Server modules (`server-auth`, `handle`) are not imported by any component (guard test).

- Typecheck and lint clean (one pre-existing warning in `postcss.config.mjs`).

### How Chris tries it
1. With the Supabase adapter env set and the #185a migration applied, sign in and open the key icon in the header (or Agent keys from the login screen).
2. Create a key with the default "Read and write". Copy the setup block once; it is not shown again.
3. Check discovery: `curl https://<deploy>/.well-known/mogmine.json` (expect `enabled: true`) and `curl https://<deploy>/api/v1/openapi.json | head`.
4. Try the key: `curl -H "Authorization: Bearer mmk_…" https://<deploy>/api/v1/me`. The request then shows in "Recent agent activity" after a refresh.
5. Revoke it: tap Revoke, then "Tap again to revoke". The next request with that key should get 401.
