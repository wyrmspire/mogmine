# API-4: Agent API point-in-time levels and VWAP endpoint

Package `API-4` (L5 Agent API, wave 6). Depends on `API-3` (candle loader) and `IN-2` (`globex-tolerant` VWAP). Design: `07` §3.4, §5, §6; decisions D-F and Q-8.

**No migration in this package.** Nothing is stored (Q-8). No `MIGRATION NEEDS APPLYING` note.

## What it does

`GET /api/v1/levels?symbol=MES|MNQ&session_date=YYYY-MM-DD&as_of=<ISO, optional>` (read scope), point-in-time on read:

- `computed`: LV-1 levels with value, `formed_at`, and window coverage.
- `withheld`: each candle level that cannot be stated yet, with `reason` and `missing_bars`. No value is invented.
- `session_so_far`: today's RTH high and low up to `as_of` (see deviations).
- `planned`: the owner's plan levels for the date as they stood at `as_of` (`planStateAsOf`).
- `vwap.rth` (strict, `gapPolicy: "complete"`) and `vwap.globex` (`gapPolicy: "globex-tolerant"`, `approximate` per D-F).
- `provenance`: `provider`, `timeframe: "1m"`, `levels_calc_version: "lv-1"`, `indicators_calc_version: "session-indicators-v1"`, `as_of`, `session_date`.

B-14: every 1m bar is kept only if `bar.time + 60_000 <= as_of`. The loader never requests a window past `as_of`.

## Deviations from the package prompt (for the planner)

1. **`session_so_far` is added.** The prompt's cutoff test expects `rth_high` to move from the 10:15 bar to the 10:16 bar. LV-1's `rth_high` is the *prior* RTH high, which does not change during the session, so that test cannot pass against LV-1 alone. `session_so_far` reports today's RTH extremes up to `as_of`, is not an LV-1 level. The OpenAPI description (`lib/agent/openapi.ts`) names it as a separate block, not an LV-1 level.
2. **The prior-session gap test removes bars from the prior Globex session as well.** PDH and PDL come from the prior session's full Globex window, not from today's overnight. The test removes five bars in each window, so PDH, PDL, ONH and ONL are all withheld.
3. **`planned` entries carry `role` (`level`, `zone_low` or `zone_high`), not `price_low` and `price_high`.** Zone edges are separate `PlannedLevel` records with no pairing key, so each edge is its own entry.
4. **PDC, pivots and ADR are not computed here.** This endpoint loads 1m bars only, with no settlement or ADR input. They are absent, not withheld, and the OpenAPI description says so.
5. **`revision_id` is the revision whose snapshot holds the levels at `as_of`**, or `null` when the plan's current levels were already in force.
6. **The 422 path is tested at the parser and command layer**, not through the full auth harness. `parseLevelsQuery` covers symbol, `session_date`, `as_of` format and future `as_of`. `buildAgentLevels` returns `invalid`, which `statusFor` maps to 422.

## Cost note

A cold call makes up to two upstream Yahoo requests (prior session and today to `as_of`). Each `as_of` gives a new cache key, so repeated calls at different instants are not cached. The shared 15-per-minute upstream limit therefore allows roughly 7 cold calls a minute per token. This is inside the 07 §5 cap, but it is a cost to watch.
