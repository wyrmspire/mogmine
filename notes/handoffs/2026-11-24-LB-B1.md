## Behaviour

- `"tap"` (default): no right-edge pills, `rightOffset` 0. Rays draw at 0.8 alpha (0.6 for settlements) and are never faded by collisions. Up to 3 price-only axis tags for the merged groups nearest entry. Trade anchors (`tone != null`) are excluded.
- `"always"`: LB-A pill column (max 8, `rightOffset` reserved), 0 axis tags.
- Tap: neighbour box, then the nearest ray within 10 px (returns the whole merged group, 4-tick), then zones, then dismiss. A neighbour tap also sends `onSelectLevel(null)` so a card does not outlive navigation.
- Pan or zoom sends `onSelectLevel(null)`. A tap of 6 px or less still does not mark a pan (the existing `PAN_DRAG_PX` logic is unchanged).

## Decisions and deviations (for the planner)

1. **Priority logic is a pure helper.** `resolveTapAction` is in `level-hit-test.ts`, so the neighbour-over-level priority is unit tested. `TradeChart` only calls it.
2. **`LevelZone` has no x extent.** The contract has no x bounds, so a zone hit spans the full pane width. No zone is passed yet, so nothing changes visually.
3. **`GROUP_TICKS = 4` is a local constant** in `level-hit-test.ts`, not an import of `MERGE_TICKS`. Importing `level-pills.ts` would pull `trades.ts` into the Chrome check. A unit test asserts the two are equal.
4. **Check script loads modules through a map.** The Chrome check stubs `lib/format.ts` (MES: `toFixed(2)`). The real formatter pulls in `trades.ts`.
5. **Geometry is read per paint.** The price-scale width settles after the first paint (324 px, then 390 px), so the check reads `lastBarX` and pane width on the same paint that drew the rays.
6. **Not in this package:** the 6 s auto-dismiss from docs/03 §3 (card UI, belongs with LB-B2). `hitTestLevel` ignores `levelLabels` mode, so taps open the card in both modes.
