## Behaviour decisions (not fixed by the spec)

1. **Restore merges, it does not replace.** A backup's record wins where it has the same `(session_date, account_id)` or the same `id`. Device-only reviews are kept. Plans replace the whole list; I chose merge because a review is hand-written text and an older or partial backup should not delete it.
2. **Over-long text is cut, not rejected** (`lesson` and point `text` at 500). The strict reject helper `validateDailyReviewInput` is not added here; `DR-1b` can add it for the command layer.
3. **Points with empty text are dropped** on load.
4. **Totals count only linked trades whose entry session equals `session_date`.** `dailyReviewTotals` passes linked trades to `buildDayCardData(review.session_date, …)`, which filters by session date. A trade explicitly linked to a review for another session is therefore not counted. Samples are always excluded.
5. `proposeTradeIds`, `unlinkedDayTradeIds`: samples are excluded unless `includeSamples` is set; the account filter applies only when `account_id` is non-null.
