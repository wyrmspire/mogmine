# FB-2: "Use HH:MM" fill-time action and pre-filled stop-move editor

Package: FB-2 (Wave 7), swarm-2, branch `swarm/FB-2`. Spec: `docs/design-2026-11-24/05-stops-mae-fills.md` §4.3, SM-UT-3.
No migration. No Supabase writes. Fixtures and unit tests only.

## What changed

- **`lib/fill-match.ts`** (+ pure helpers)
  - `buildMatchedFillPatch(trade, role, matchedBarTimeMs)` returns `{ patch, undoPatch }` or `null`. It writes the UTC ISO of the matched bar to `entry_time` or `exit_time` and recomputes `trade_style`. `undoPatch` restores the original time and `trade_style`. It returns `null` when the entry would be `>=` exit, when an exit is moved on an open trade, or when the time is not finite.
  - `requestStopMovePrefill(tradeId, price)` and `subscribeStopMovePrefill(listener)` are a module-level pub/sub. Unsubscribe removes the listener. Nothing is written to the store.
- **`components/DataNotesChip.tsx`**
  - `use_matched_fill` notes get a `tool-button num` (44px) with the note's own label, "Use 14:13". A tap calls `updateTrade` and shows a toast "Entry time updated to 14:13" with an Undo that applies `undoPatch`.
  - `edit_untimed_stop` notes get an "Add time" button (44px). A tap calls `requestStopMovePrefill` and scrolls `.stop-moves-editor` into view, smooth or `auto` under `prefers-reduced-motion`.
- **`components/StopMovesEditor.tsx`**: subscribes to the prefill for `trade.id`. It sets the new-move price to `price.toFixed(decimals)`, clears the error, and focuses the time input with `preventScroll`. It saves nothing.
- **`lib/__tests__/data-notes-actions.test.ts`** (new, 6 tests): Trade C `Use 14:13` round trip, exit patch, two ordering guards, non-finite guard, pub/sub delivery and unsubscribe.

## Deviations from the prompt (and why)

1. **Trade id comes from the route, not the note.** `DataNote` carries no trade id, `data-notes.ts` is not in the writable list, and `TradeDetail.tsx` is off limits. The chip reads the id from `usePathname()` (`/trades/[id]`) through an exported `tradeIdFromPath`. The chip shows its action buttons only when it can resolve the trade.
2. **No `prefillMove` prop on `StopMovesEditor`.** The pub/sub covers it, and a prop would have added lines to a file that must not grow.
3. **Button label.** The note's `action.label` is already "Use 14:13", so the button renders that label. Rendering `Use {label}` would have shown "Use Use 14:13".
4. **`buildMatchedFillPatch` takes `trade_style` in its `Pick`.** Undo needs the original style. It does not take `id` or `status`; it keys off `exit_time`.
5. **Not verified: the `390×844` visual check.** No browser run was done in this lane. The chip and editor changes are not covered by a DOM test.
