## Decisions and deviations (for review)

1. **`buildReviewCardCopy` lives in `lib/day-sheet.ts`.** It is pure, and the node test runner cannot import `.tsx`. `ReviewCard.tsx` re-exports it, so the spec's import path still works.
2. **Chart snapshot.** `ReviewChart` and `TradeChart` expose no screenshot ref, and both are outside this package's writable files. `captureChartCanvas` composites the chart's DOM canvases at 2×. Position boxes are included because they draw on those canvases. HTML overlays are not. The clean fix is a `screenshot` ref on `ReviewChart` / `TradeChart`, which needs an owner decision.
3. **Snapshots are keyed by trade and privacy.** While the Share sheet is open, the cards behind it render with the export's Shield, so every chart in the export matches the export's privacy. A chart missing for the export gets a "Chart not in this export" placeholder.
4. **Summary band is drawn directly** in `day-sheet.ts`, not by `renderDayCardCanvas`. That function draws a complete fixed-layout Day Card and cannot be used as a band.
5. **Only linked trades get cards.** Unlinked candidates stay as compact rows, so unlinked trades do not trigger candle fetches.
6. **"Candles unavailable"** is my own placeholder for candle status `none`. Loading and ready states still go through `ReviewChart`.
7. **Open trades**: result reads "Open", risk shows "said X" when there is no stop.
8. **`app/review-day.css` was not edited** (out of scope). Card styles live in `ReviewCard.tsx`.
