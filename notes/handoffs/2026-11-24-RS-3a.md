# [RS-3a] Switch library consumers to account R (`resultR`); rename stop-width `rMultiple` → `riskMultiple`

**MIGRATION: none.** No Supabase, schema or env change. Pure library code and tests.

Decisions followed: **D-A** (everything labelled "R" is account `resultR`; stop-width ratio is `riskMultiple`, shown as `× risk` / `R:R`), **D-C** (`isScratch` stays on the trade's own stop risk). Design: `docs/design-2026-11-24/04-r-size.md` §3.1, §3.5, §6.

## What changed

| File | Change |
| :--- | :--- |
| `lib/trades.ts` | `rMultiple`→`riskMultiple`, `initialRMultiple`→`initialRiskMultiple`, `plannedR`→`plannedRewardRisk`. Old names kept as `@deprecated` aliases (for `components/*` until RS-3b). `isScratch` unchanged. New exported type `RSizeOptions` (`accounts?`, `prefs?`). | `lib/exit-efficiency.ts` | Ratio unchanged (unit-free). Summary R in account R, 2 dp. MFE in account R = MFE dollars ÷ R size. Falls back to points when R cannot be computed, as before. Optional 3rd arg `opts`. |
| `lib/plan-vs-actual.ts` | Price differences in account R (dollars ÷ R size). Result row planned text is `R:R 2.0:1 at target` (never `2.0R`). Optional 2nd arg `opts`. |
| `lib/__tests__/account-r-consumers.test.ts` | **New**, 11 tests (see below). |
| 7 listed existing test files | Assertions updated (see table below). |

Two deliberate choices:
- **Pure default for consumers without options.** The package prompt suggested falling back to `getAccountsState()` inside `resolveRSize(trade)`. I did not do that. These modules are pure and must not import the store. Without options, `resolveRSize` uses the trade's snapshot, then the default `$250` (`prefs` not passed). UI callers that need an account size pass `accounts`/`prefs` (done in `shareCard`, `day-card`, `selectors`, `exit-efficiency`, `plan-vs-actual`).
- **`r-size.ts` was not changed.** It is not in the writable list. It already has `resultR` and `resolveRSize`.
