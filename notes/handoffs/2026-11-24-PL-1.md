## Decisions

- **Feed parity:** every `feedHref` is built with `filtersToQuery`. The test runs `applyFilters(eligible, parseFilters(href))` and asserts it equals `n` for playbook, setup/execution-tag rows, tag, tag × playbook, unknown tag, matrix cell, `noPlaybookHref` and `impulseHref`. It runs with samples on and off.
- **Open trades (OD-38):** they count in `n`, `openCount` and `lastUsedAt`. They are excluded from R, rules, wins/losses/scratches, hold bands, exit reasons and stop-moved counts. "Done" means `!isOpen`.
- **Gates (`PLAYBOOK_CARD_MIN_TRADES` = 10):** `avgResultR` needs 10 closed trades with an R value. `rulesFollowedRatio` needs 10 graded closed trades. Rules-followed is the UX-13 definition, the same one `runningStats` uses: trades with every rule followed ÷ graded trades.
- **Shape facts:** `longCount`/`shortCount` cover all trades. Exit reasons, hold bands, stop-moved, wins/losses/scratches cover closed trades. `stopMoved` means `stop_moves` is non-empty. `stopMovedShare` is not gated.
- **Examples:** up to 3 distinct ids, ids only. `latest` is the most recent trade of any kind, including open. `best_rules` and `latest_loss` come from closed trades. Duplicates are dropped, so a single trade fills every role but is listed once.
- **Ordering:** active playbooks before archived, input order kept within each group. Tags are setup then execution, in vocabulary order. Tag × playbook and tag rows sort by count, descending.
- **Matrix:** sparse. Only cells with `n > 0` are emitted; the UI fills zeros.

## Known gaps for PL-2a/2b (flagged, not fixed)

1. **`gaps.noSetupTagHref` is a superset.** `noSetupTag` lists trades with a playbook and no setup tag, per `01` §4.5. The Feed filter can't also filter by playbook, so `tag=no-setup-tag` also returns no-playbook trades. The test does not assert parity for this link. Options for the planner: add a Feed filter combo, or accept the superset.
2. **Reserved-value collisions (edge).** A quick tag literally named `no-setup-tag` or `none`, or a playbook id `none`, makes the Feed read it as a filter sentinel. Parity would break for those labels. Playbook ids are generated slugs, so this is unlikely.
3. **Orphan playbook ids.** Trades whose `playbook_id` matches no playbook in the list count in `withPlaybook` but appear in no playbook facet.
4. Setup-tag membership uses `tags.setup`, not the `SETUP_TAGS` constant that `applyFilters` uses for `no-setup-tag`. They agree while the vocabulary is the constant (PL-3 changes that).
