# SL-12 — Recipe list + editor (form + JSON)

Spec: `docs/design-2026-11-24/09-strategy-lab.md` §5, §12.3, §12.4, §14 row SL-12. Depends on SL-8 (merged, `821c4bc`).

## What shipped

- `components/StrategyLabRecipes.tsx` — recipe list per playbook (newest version per recipe, `+ New`, optional run-summary line per recipe supplied by the parent, link to `/playbooks/lab?playbook=<id>`). 82 lines.
- `components/StrategyLabRecipeEditor.tsx` — `[ Form | JSON ]` editor. Both tabs edit one draft, so switching tabs cannot drop a value. Live validation; every error prints its path (`trigger.all[1].value`). Save goes through `commitDraft`. 447 lines.
- `lib/strategy-lab/recipe-draft.ts` — **new pure module** (see deviation). Path-based immutable edits, draft ↔ JSON, trigger rows, slice chips, and `commitDraft` (version bump rule). 238 lines.
- `lib/__tests__/strategy-lab-editor.test.ts` — 22 tests.

## Acceptance

- **Form ↔ JSON round trip:** form edit → JSON → parse gives an identical draft; a stored recipe (§5.3 example A) survives draft → JSON → validate with a deep-equal recipe.
- **Version bump on edit after a run:** a changed recipe whose newest version has runs appends v+1 and keeps v as it was. No-run recipes are fixed in place. An unchanged save does not bump. An invalid draft leaves the store untouched.
- **Validator errors with paths:** empty trigger (`trigger.all`), bad value (`trigger.all[0].value`), unknown output (`.out`), unknown skill (`.skill`), measure in trigger (`.skill`), window/sizing/stop (`window.startEt`, `sizing`, `stop.points`), bad JSON and non-object root (path `""`).
- **R rule:** sizing is `risk-r` in R units only. The editor shows the R basis label passed in as `rSizeLabel`. No stop-width-as-1R anywhere.

## Deviation (please review)

Node cannot load `.tsx`, so the pure model cannot be tested from inside a component file. The writable list has no `lib/` file for it, so I added one new file, `lib/strategy-lab/recipe-draft.ts`. Nothing existing was edited. If the planner prefers the model inside the component, the test would have to read source text instead, which is weaker.

## Not wired (needs a later package)

- Neither component is mounted. `app/strategy-lab/page.tsx` is SL-7's and not in my writable list. The Recipes tab wiring belongs with SL-10 / SL-13.
- MVP keeps no run store, so the parent must pass `newestHasRuns` (drives the version bump) and `lastRuns` (list summaries). After a bump, the editor sets its own `runsOnNewest` to false.
- Editor is keyed by the parent: mount with `key={recipeId ?? "new"}` so the draft resets per recipe.
- Measure, account, and slippage are edited in the JSON tab only. Nested triggers (any / not / nested all) show a JSON-only note.
