## What is built

- **Map.** Grid when there are 8 or fewer setup tags, with rows = active playbooks plus archived ones with trades. Columns = setup tags. Cell shade is `color-mix(in srgb, var(--gold-mid) calc(N% * var(--gold-intensity)), var(--bg-elevated))`. Nothing encodes profit or loss. Non-zero cells link to the Feed. When there are more than 8 setup tags, it switches to a pairs list sorted most used first.
- **Gaps.** No-playbook and no-setup-tag counts (link), impulse count plus share (link), never-used playbooks (link to `/tune#playbooks`) and never-used tags. Clean state reads "Every trade has a playbook and setup tag."
- **Scroll.** `.lab-map-scroll` scrolls horizontally inside its own box. The first column is `position: sticky; left: 0`. The page-level `.lab-page { overflow-x: clip }` from PL-2a is unchanged.

## Deviation

- Cells with `n > 0` get at least 1% shade, so a small count is never invisible. The spec formula rounds to 0% in that case.

## BLOCKER 1: Gaps no-setup-tag link does not return its count

`gaps.noSetupTagHref` is `/feed?tag=no-setup-tag`. `matchesFeedFilters` (`lib/selectors.ts:180`) matches every trade with no setup tag, including trades with no playbook. The model counts only trades that have a playbook (`lib/playbook-lab.ts`, `noSetupTag`). The mismatch is therefore whenever a trade has neither a playbook nor a setup tag. Feed count vs displayed count, from the fixture in the todo test: **4 vs 3**.

Fix needs a file outside this package's writable list. Either a combined Feed filter (`playbook` and `tag=no-setup-tag` together, meaning playbook is set and no setup tag), or a model change that links to a new filter. The test is written as `todo` with the reason and fails visibly as todo.
