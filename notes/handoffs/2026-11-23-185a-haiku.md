## Deviations from the brief (with reasons)

1. **Auth runs before the body is read.** The brief put the body read first. Reading after auth means an unauthenticated caller cannot make the server parse a body, and a bad body (400/413) is audited like any other post-auth failure.
2. **`prompt_library` is not exposed.** The brief lists it as a singleton, but the adapter keeps it in module memory (docs/26 §4), so a PUT would appear to succeed and vanish on the next request. Only `prefs` and `mood_registry` are exposed. Singleton keys are the v1 singletons in the registry.
3. **Response shapes.** List returns plain records (as briefed). Single read, create, update, archive and singleton return `{ record, meta }` (or `null` for an unset singleton), so the agent can see `updated_at`. Delete returns `data: null`.
4. **Audit also covers refused requests that already resolved an owner.** A scope refusal (403) or a session failure (503) is audited, because the key and owner are known. Unknown or revoked keys are not audited, since no owner is known.
5. **Unexpected exceptions after auth are not audited.** They return a generic 500 with no detail.
6. **DB lookup failure** returns 503 `unavailable` (the brief did not specify a code).
7. **Route builder mirrored in the test.** The test does not import the route files, because they use the `@/` alias and node:test cannot resolve it. The route files are typechecked and both builds compile them.
8. **Off-switch uses `chooseAdapter` from `lib/persistence/select.ts`, unchanged.** It is not React-bound (see Fix 1).

## Summary

## Security notes
- Keys are stored as SHA-256 hashes only. The plaintext is never logged or echoed.
- The service role is used for three things only: lookup by hash, minting the owner's session (no email sent), and writing `last_used_at` and the audit row. It never reads or writes a journal table.
- Scopes: `read` for GET, `write` for other methods. `write` does not imply `read`.
- Unknown and revoked keys get the same 401.
- Rate limit: 120 requests a minute per key, per server instance (best effort; not shared across instances).
- Minting a session replaces any magic link the owner requested but has not opened. Owners should sign in on their phone before agent use.
- Server-only modules are guarded in `lib/__tests__/auth.test.ts`. The server import graph is guarded in `lib/__tests__/server-import-graph.test.ts`.
