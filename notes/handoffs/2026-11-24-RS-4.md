## What the UI does

- Tapping a preset sets `statedRiskR`; tapping the active preset clears it. `Other` opens a decimal field (0.01–10, two decimals).
- With the stop **empty** and a valid entry and stated R, a `Use stop 7122.00 ($75)` button offers the stop. It never fills a typed stop.
- With the stop **typed**, a live line shows `Stop 7119.50 → $87.50 (0.29R) · you said 0.25R`. Under Shield: `Stop 7119.50 → 0.29R · you said 0.25R`, no dollars.
- Submit blocks on an invalid stated R. Saves `stated_risk_r` (null when unstated) and `r_size_cents: rSize.cents` (the R size resolved from the account, frozen per D-B).

## Choices I made (the planner may want to redirect)

1. **Stop rounding.** The "Use stop" price rounds the distance **up** to whole ticks, away from entry. So the risk is never smaller than the stated R. 0.26R on $300 is 15.6 pts, which lands on 15.75 pts (7121.25).
2. **Backfill takes repos, not the command layer.** `runBackfillDryRun({ repos, owner, prefs? })` and `runBackfillApply(source, rows)`. The spec asks for `repos.trades.put(owner, updated, { expectedUpdatedAt })`, and the command layer's `update` does not expose `expectedUpdatedAt`.
3. **CSV has one extra column, `updated_at` (last).** The `expectedUpdatedAt` for the conflict check has to come from the dry run. Without it, apply can't detect an edit made in between.
4. **Apply writes what the reviewer confirmed.** `proposed_stated_risk_r` (edited by Chris in the CSV) becomes `stated_risk_r` when non-empty. Empty keeps what is stored. Note fields are never read for writing.
5. **`r_size_cents` is written only where the trade has none** (the frozen value wins, D-B). `risk_cents` is always recomputed with `riskCents`.
6. **Proposal rule.** `proposeStatedRiskFromNotes` returns `null` when no note mentions an R amount. Otherwise `{ proposed_stated_risk_r, notes_have_risk_text: true }`. The proposal is the single distinct amount in (0, 1]. Two different amounts give a `null` proposal, so Chris picks.
7. **CLI reads a backup file, not live storage.** `--input <backup.json>` is the only data source. Apply writes a **new** file (`--out`, refused if it equals `--input`). It never touches Supabase or `/api/v1`. The file-mode concurrency token is the backup's `exportedAt`, so a CSV goes stale when the backup file changes. **Wiring the CLI to the live store is not in this package.** It needs Chris's go-ahead for that step.
