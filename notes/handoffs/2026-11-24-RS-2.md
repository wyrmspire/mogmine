## Decisions and one scope note

- **Out-of-scope file: `lib/risk-line.ts` (new).** The package names `formatRiskLine` as an export of `components/RiskLine.tsx`. The existing test runner only loads `.ts` files (`node --test lib/__tests__/*.test.ts`), and a `.tsx` module cannot be imported there. So the pure formatter lives in `lib/risk-line.ts`, and `RiskLine.tsx` re-exports it, so the component's public export is unchanged. No other lane owns this path. The integrator should accept or move it.
- **Stated R dollars are priced in the trade's own R size.** On a trade with a $250 default, `0.25R` reads `($62.50)`, not `($75)`. The golden `$75` case is the $300 account.
- **Source hints** read "R size from <account>", "R size frozen on this trade", "<account> has no R size yet", or "No account on this trade · using your default". The `prefs` case never names the amount, so Shield-safe.
- **Shield:** the risk line takes `renderPrivacy` (the card-preview aware flag, as the package says). The `RiskChips` dollar parts still use `prefs.shield`, as before.
- **Chips and risk line both show with no stop.** The chips keep their own "No stop recorded." text. The risk line shows the same words above them. The duplicate is intentional for now; the integrator can drop one.

## Not done / not verified

- **Browser check at 390×844 (overflow and 44px taps): not run.** `/usr/bin/google-chrome` exists, but no Playwright or Puppeteer driver is installed, so a scripted `scrollWidth` and tap-target check could not be made. Tap targets are set with inline `minHeight: 44` on every new button and input; the new rows use `chip-row`, which wraps. This needs a visual check by the owner or the integrator.
- The RS-3a / RS-3b consumers (`rMultiple` → `resultR`) are untouched, per scope.
