## Choices the spec did not settle (for the planner to confirm)

1. **beyond-swing with `maxPoints`.** A swing stop wider than `maxPoints` skips the trigger bar (counted under `stop` / `bad-params`), so it never becomes a trade. The spec says "max 10 pt" and does not say cap or skip. I chose skip, because capping would change the risk the trader is looking at.
2. **Swing lookback is session-bounded and includes the trigger bar.** It matches `structureStop` (bars `i−lookback+1 … i`).
3. **Measure outputs go into `Match.features`,** keyed with `featureKey` (for example `levelReach@1:reached(level=onh)`, `forwardReturn@1:…(forwardMinutes=15)`). `Outcome` is frozen by SL-1 and has no slot for them. SL-9/SL-10 can read them from there.
4. **`overlays` is `[]`.** The overlay (SL-11) needs trade records, which the runner signature does not take. The field is in place.
5. **Find-similar slices include number outputs without buckets** (for example `contextRanges.weekPosPct`, `mtfCandle.lowerWickPctile`). §10.4 says "buckets or categories", but the §5.3 example A uses these, so I followed the example. Attribution falls back to terciles for them.
6. **Find-similar also sets `measure`** to example A's list (`vwap_globex`, `onh`, `pdc`; 15/30/60 min). §10.4 does not specify it.
7. **Find-similar computes its own readings** from the same skills at the mark, rather than importing SL-7's Context Card model (`context-card.ts` is not in this worktree). If SL-7 lands with a different reading, the two should be unified.
8. **Store versioning.** A plain re-save replaces the newest version; `newVersion: true` appends. SL-12 should pass `newVersion` when the recipe has runs.
