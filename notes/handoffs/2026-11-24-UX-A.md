## Deviations and open items

1. **Past-day header kept.** `formatDayTradeHeader` says "today", so for a past day `TodayScreen` keeps its existing "N trades that session" wording. Applying the helper there would read "3 trades today" on a Tuesday.
2. **Type name.** The prompt says `SessionReviewResult`. The code's result type is `SessionReview`, so `writtenAfterClose` went on that interface.
3. **Until dropdown for a late plan.** For a late unanchored plan, `reviewWindow` ignores `until` (the spec returns the fixed session bounds). The "Until" select in `SessionReview` still lists later checkpoints of the same day, but choosing one does not change the window for that plan. Planner decision: either hide the select when `writtenAfterClose`, or let `until` shorten the late window. I did not change it because the spec is explicit.
4. **Nav badge.** `AppShell.tsx` (not touched) computes `waiting` as `review_status === "new"` over `withSamples(...)`. `TodayScreen` and `ReviewScreen` use the same rule, so the "needs tags" counts agree.
