# R3-03 — Volume 0 and incomplete 1m buckets are missing volume in aggregateCandles

Spec: `docs/16-floor-roadmap.md` §4.3 (Refine MD-1), `MOGMINE-BLUEPRINT.md` §3.7 ("Volume 0 means missing").

## What changed

- **`lib/candle-aggregation.ts`** (new, 113 lines, relative `.ts` imports only): `aggregateCandlesWithMeta` and `aggregateCandles`, plus the `AggregatedCandleMeta` and `AggregateOptions` types.
  - `sourceMinutes` is inferred from the minimum positive spacing between adjacent input bars, clamped to `[1, minutes]`, when it is not passed in.
  - `expectedBars` is `1` when the source is at least as coarse as the target. With `symbol` it counts regular-session source instants via `isRegularTradingBarInterval` (minimum 1). Otherwise it is `round(minutes / sourceMinutes)`.
  - Volume is `sum` only when the bucket is complete and every constituent has `Number.isFinite(v) && v > 0`. Otherwise it is `0`, never `NaN`.
  - `aggregateCandles(candles, "1m")` with no options still returns the input array unchanged.
- **`lib/trades.ts`**: the in-file `aggregateCandles` is replaced by a re-export of both functions and their types from `./candle-aggregation.ts`. No new logic lives here.
- **`lib/__tests__/candle-aggregation.test.ts`** (new, 89 lines): covers the five acceptance cases, plus a 1m passthrough and meta check.

## Behaviour change to know about

`aggregateCandles` without options now returns `volume: 0` for incomplete buckets and for buckets with a zero-volume constituent. Previously it returned a partial sum. This is the intended §3.7 behaviour. Callers that render volume should check `hasRealVolume` in `lib/volume.ts`. That file is read-only for this package and was not changed. `TradeDetail.tsx` calls this function for display, so volume bars on higher timeframes can now show as absent where they used to show a partial sum.
